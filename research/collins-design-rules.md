# Collins-Level Website Design Protocol: Working Extract

Source: "Collins-Level Website Design Protocol" PDF, pp. 1-35 (all read). Section numbers below are the PDF's own (S1-S25); "P" = printed page. The PDF is a process and gate document. It gives NO numeric type scales, spacing values, easing curves, durations, or contrast ratios (see section 4). 

## 1. Core rules (imperative, tagged)

1. Aim for clear, ownable, culturally relevant, commercially useful, accessible, verified. "Modern/clean/premium/award-like/AI-generated" is not a standard. (S1, P1)
2. Make the site easy to understand AND hard for competitors to imitate honestly. (S1)
3. Start from customer, problem, outcome, positioning, content, proof, constraints, governing idea. Never start from mockup, template, palette, animation, framework or AI hero. (S2.1)
4. Express belief, behavior, why-now, difference, and reason to believe. Never decorate to cover weak positioning. (S2.2)
5. Never make users decode: what you do, where they are, what is clickable, how to navigate, what next, what happens after an action. Creativity must not add confusion. (S2.3)
6. Let real content set structure, order, type, scale, imagery, pacing, interaction. Do not force content into generic cards. (S2.4)
7. Design a system across pages, breakpoints, states, languages, content lengths, future updates. (S2.5)
8. Claim nothing (usable, accessible, responsive, fast, distinctive, complete, production-ready) without evidence. (S2.6)
9. Lock before work: mode, outcome, target, ONE primary action, constraints, protected assets, proof, commercial value, classification (SELL/USE/MERGE/PARK/ARCHIVE). (S3)
10. Stop if no audience, outcome, primary action, owner, or protected list; if duplicating an asset; or if design is avoiding selling or customer contact. (S3 stop condition)
11. Pass Gate One: "When [situation], [customer] needs to [job], because [stakes], but [barrier], so they can [outcome]." (S4)
12. Write positioning: "For [audience], [brand] is the [category] that [value], because [evidence]. Unlike [alternative], we [difference]." (S5)
13. Reject positioning built on innovative, cutting edge, quality, passionate, tailored, customer-first, excellence, creativity, empowerment unless made concrete and evidenced. (S5 Gate Two)
14. Translate each brand adjective into visual, content, and interaction behavior. Cap experimentation at ONE controlled signature interaction. (S6)
15. Connect every visual decision to positioning, customer need, content, brand behavior, or function. (S6 Gate Three)
16. Source references beyond websites and beyond your sector. Record what to extract, what not to, and copying risk. Extract principles, never imitate. (S7)
17. Write a project-specific cliche blacklist before design. (S7)
18. Classify every content element: keep verbatim, keep and reposition, rewrite with approval, replace with evidence, remove, missing and required. (S8)
19. Sequence the page: orientation, relevance, differentiation, explanation, evidence, objection resolution, action, confirmation. (S8)
20. Preserve customer language; remove repetition and generic AI copy; make headlines communicate. (S8)
21. Give every page a name, user, situation, purpose, primary question, primary action, required proof, entry, exit, success metric. (S9)
22. Explore at least three materially different territories (restrained, expressive, experimental), all usable. A human owner picks; never silently average them. (S10, Gate Four)
23. Prove structure in grayscale with real content, basic hierarchy, no effects, before polish. (S11)
24. Pass the wireframe test: without styling, a user knows what, who, offer, why it matters, why credible, what next. (S11)
25. Test behavior (explain, locate, find proof, complete action, recover from error), not taste ("Do you like it?"). (S12)
26. Fail the design if users repeatedly ask: where am I, what does this mean, is this clickable, what next, how go back, why this info, did it work. (S12 Krug gate)
27. Ask of imagery: could a competitor own it, does it hold without the logo, is it rooted in the real story, is any of it proprietary, does it make memory not polish. (S14)
28. Prototype with approved copy, real imagery, real field and content lengths, all states, reduced-motion variant. (S15)
29. Every animation serves hierarchy, orientation, feedback, narrative pacing, or brand expression. (S16)
30. Justify every component. Reject any that exists because of a template, fashion, library convenience, need for variety, or another award site. (S17 Gate Five)
31. Specify testably. Ban "make it premium / more dynamic / add animations / Awwwards-level / luxury feel." (S18)
32. Build one verified slice (landing, offer, proof, conversion, confirmation, analytics event) before scaling the system. (S19)
33. The builder never approves itself; six independent reviews. (S20)
34. Report with evidence: decision, changes, proof, status by phase, commercial impact, risks, rollback, one next action, exact human approval needed. (S24)
35. Surprise only after understanding. (S25)

## 2. Rubric, gates, checklists

**Score each 0-10 (S21, P28):**

| Category | Weight |
|---|---|
| Strategy and positioning | 12% |
| Customer understanding | 8% |
| Content | 10% |
| Information architecture | 8% |
| Usability | 14% |
| Visual design | 12% |
| Originality and art direction | 12% |
| Responsive design | 7% |
| Accessibility | 7% |
| Performance and reliability | 5% |
| Conversion and proof | 3% |
| Ownership and rollback | 2% |

**Release requirements (P29):** overall >= 8.5; usability, visual design, originality, accessibility each >= 8.5; primary conversion flow >= 9.0; zero critical failures, broken controls, mobile overflow, unverified claims; rollback documented; owner approval recorded. "A high average cannot hide a critical failure."

**Gates:**

| Gate | Pass condition |
|---|---|
| 1 Discovery (S4) | Situation/job/stakes/barrier/outcome sentence |
| 2 Positioning (S5) | No unevidenced buzzwords |
| 3 Brand (S6) | Every visual choice has a rationale |
| 4 Territory (S10) | Human owner selects |
| 5 Components (S17) | No component without a reason |
| Krug (S12) | Users do not repeatedly stall on the seven questions |
| Council (S20) | Six reviewers: customer-value, Krug usability, creative director, accessibility, technical, sovereignty |

**Compact checklists to reuse (P12-P31):**
- Content: headline communicates; audience recognizable; offer concrete; benefit clear; claims evidenced; objections answered; CTAs specific; scannable; legal text present; ownership of updates documented.
- Prototype states: default, hover, focus, active, disabled, loading, empty, error, success, expanded, collapsed, mobile, tablet, desktop, reduced motion. Also: real, long and short content fit.

## 3. Anti-slop / anti-template patterns

**Cliche blacklist (S7, P11):** generic centered hero; purple-blue gradients; glassmorphism; floating dashboard mockup; three-card feature row; default bento grid; pill-shaped everything; generic geometric sans; random luxury serif; stock lifestyle photography; decorative 3D spheres; endless marquee; arbitrary parallax; template testimonials; fake metrics; AI brain imagery; unnecessary rounded rectangles.

**Auto-reject (S23, P32):** starts from a template without strategic justification; hero could belong to any competitor; every section centered; same rounded card everywhere; gradients form the identity; unrelated stock; vague AI copy; motion without purpose; usability sacrificed for novelty; type chosen only to look luxurious; polish hides an unclear offer; mobile is compressed desktop; unusable by keyboard; conversion flow untested; deployment presented as proof of completion; builder is the only reviewer.

**Motion rejects (S16):** long intros blocking content; scroll hijacking; motion on every section; hover-only information; delayed button response; text reveals that slow reading; parallax without narrative purpose; cursor effects required for navigation; no reduced-motion alternative; multiple unrelated animation languages.


## 4. Concrete implementable rules (and what is NOT specified)

Specified numbers/limits:
- Mobile acceptance test at 390px width: no horizontal overflow, headline fully visible, CTA reachable without overlap, nav opens by keyboard and touch, hero keeps defined focal point (S18, P25).
- Max ONE signature interaction (S6); exactly ONE primary action per page (S3, S9); three territories minimum (S10); six reviewers (S20).
- Motion: each animation needs a function from the list of five; reduced-motion alternative required for every one; define a performance budget and mobile simplification (S16 spec fields).
- Mobile: designed separately, intentional content order, nav transforms, "touch targets sufficient", media keeps focal points, mobile crops defined, acceptable mobile performance (S22).
- Imagery: owned or licensed; consistent treatment; mobile crops, alt text rules, video posters, optimized dimensions, AI artifacts inspected, representation and cultural review; stock "justified or rejected" (S14).
- Type: define display hierarchy, readable body, controlled line lengths, leading, optical tracking, mobile line breaks, fallback, font-loading optimization, licensing (S13). Grid: define columns, margins, gutters, baseline rhythm, container widths, alignment rules, controlled exceptions, mobile and wide-screen behavior (S13).
- Color: functional roles, tested contrast, color never the only information carrier (S13).

NOT in the PDF: modular type scale or ratio, px/rem spacing steps, line-length numbers, touch-target pixels, durations or easing values, contrast ratios, image weight limits. The team must set these as tokens and write them into the build spec (S15 requires exact instructions). Set these as team tokens, labeled as team decisions.

## 5. Conflicts with, or tightening of, the existing documents

| Existing rule | Protocol effect |
|---|---|
| 100-point audit: hierarchy | Aligned (wireframe "hierarchy works without color"). Tightens: test in grayscale. |
| Proof before claims | Aligned and stricter: "Unverified claims: zero" is a release blocker; fake metrics are blacklisted. |
| Subtraction before addition | Not named. Closest: "no component exists only to fill space," Gate Five, remove/replace content classes. Add as team rule. |
| Mobile as separate design mode | Aligned; "mobile is a compressed desktop" is an auto-reject; zero mobile overflow gate. |
| No self-approval | Aligned; adds six named reviewer roles including accessibility and sovereignty, plus recorded owner approval. |
| 100-point scale | Protocol scores 0-10 with different weights (usability 14%, conversion and proof only 3%). Pass mark 8.5 is roughly 85/100 if mapped. Keep both; do not merge weights silently. Tension: conversion and proof weigh 3% but the flow must score >= 9.0. Treat the 9.0 as a hard floor, not a weighted item. |
| One dominant conversion | Same, enforced earlier: Project Lock "single most important conversion." Per-page primary action is mandatory. |
| Strategy before styling | Same; adds Gate One sentence, Gate Two buzzword ban, and stop condition "design used to avoid selling." |
| Three creative territories | Tightens: must be restrained, expressive, experimental, each with 16 fields (incl. imitation risk, accessibility risk, performance risk); human owner chooses; no averaging. |
| Design lock | Protocol has no single "lock" but Gates 3-5 and the build spec (S18) serve it; add that approved tokens/content/assets are frozen. |
| Adversarial gauntlet | Protocol council = six reviewers plus Krug gate with real user tests. Tighten: use real users (S12), not just reviewer agents. |
| Production proof | Tightens: deployment is never proof; require analytics event evidence, tested conversion, error states, rollback tested. Build one verified slice first (S19). |


## 6. Landing page design brief: nonprofit web-presence audit

**Project lock.** MODE: [greenfield/brownfield]. OUTCOME: [N] qualified audit bookings per [period]; baseline [CURRENT RATE or "unknown, instrument first"]. TARGET: small and mid-size nonprofit and social-purpose company leaders (ED, comms or development lead, founder) [confirm via interviews]. PRIMARY ACTION: [Book / request audit] (single). PROTECTED: [SELLER] name, logo, approved copy, domain. PROOF REQUIRED: [CASE STUDY], [before/after], [sample audit page], [named quote with permission]. Stop if proof is missing: label it MISSING AND REQUIRED, do not invent.

**Gate One sentence (draft, validate).** When a funder, donor or board member judges the organization by its website, a nonprofit leader needs to know what is weakening that first impression, because trust and funding follow, but they have no time or design staff to diagnose it, so they can fix the few things that matter.

**Positioning (fill, do not invent).** For [AUDIENCE], [SELLER] is the [CATEGORY: web-presence audit] that [VALUE], because [CASE STUDY / method evidence]. Unlike [ALTERNATIVE: agency redesign, DIY checklist, free grader], we [DIFFERENCE]. Avoid every Gate Two buzzword.

**Governing idea (territories, human picks one).** Restrained: the audit as annotated document, dense and editorial. Expressive: [SELLER]'s own diagnosis visualized on a real nonprofit page. Experimental: one signature moment, a before/after reveal driven by the user, with a static fallback. All usable; imitation risk recorded.

**Page narrative (S8).** Orientation (what the audit is, for whom) > relevance (the funder-first-impression moment) > differentiation > explanation (what is scored, what they receive) > evidence ([CASE STUDY], sample audit excerpt, [QUOTE]) > objections (cost, time, "we will redo the site anyway," no tech staff) > ONE action > confirmation (what happens next, timing [X]). Repeat the CTA at most once more.

**Subtraction.** No section outside the sequence above; no unapproved metrics, logos, testimonials.

**Type, grid, color.** Define as team tokens: display and text faces with licensing and fallback; line length; leading; written grid; tested contrast. Avoid the blacklist.

**Imagery.** Real work: annotated screenshots of actual (consented) nonprofit pages, [SELLER] documents, genuine people and places. No stock lifestyle, no AI brain imagery. Mobile crops and alt text defined per image.

**Motion.** Allowed only for orientation, feedback, or the single signature moment. Reduced-motion variant, no scroll hijack, no hover-only content, nothing delays the CTA.

**Mobile (separate design).** Own content order (offer, proof, CTA first); tested at 390px: no overflow, headline whole, CTA clear, nav by touch and keyboard, focal points kept; sticky CTA only if it does not cover content.


**Acceptance and proof.** Score 0-10 per S21 and meet release floors (overall >= 8.5, usability/visual/originality/accessibility >= 8.5, conversion flow >= 9.0, zero critical, zero unverified claims). Verify: five-user task test (explain the offer, find proof, book, recover from error), keyboard and screen-reader pass, analytics event firing on conversion, performance budget [set], rollback documented, owner approval recorded. Then, only then, scale.
